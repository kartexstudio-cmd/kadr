## Шаг 2. Запустить сайт локально

Открой **Командную строку** (нажми Win, набери `cmd`, Enter) и выполни:

```
cd C:\Cloude\studio
npm run dev
```

Открой в браузере **http://localhost:3000** — перекинет на `/ru` или `/en`, в зависимости
от языка браузера. Остановить сервер — `Ctrl+C` в том же окне.

### Если не запускается

**`npm` не распознан как команда.** Node.js установлен (`C:\Program Files\nodejs`) и
прописан в системном PATH, но уже открытые окна терминала об этом не знают. Закрой
терминал и открой заново.

**В PowerShell ошибка «running scripts is disabled on this system».** PowerShell по
умолчанию не выполняет скрипты, а `npm` в нём — скрипт. Поэтому я советую обычный `cmd`.
Если хочешь остаться в PowerShell — добавляй `.cmd`:

```powershell
npm.cmd run dev
```

Либо один раз разреши скрипты своему пользователю (это меняет настройку системы):

```powershell
Set-ExecutionPolicy -Scope CurrentUser RemoteSigned
```

**Порт 3000 занят.** Next.js сам предложит 3001 — просто согласись.

**В bash / Git Bash `npm` не виден:**

```bash
export PATH="/c/Program Files/nodejs:$PATH"
```

## Шаг 3. Подключить приём заявок (Supabase)

Сейчас форма работает и говорит «спасибо», но заявки **никуда не сохраняются** — база не
подключена. Код для записи уже написан, нужно только создать базу и вписать ключи.

> Claude: `Помоги подключить Supabase к форме заявок по Шагу 3 из HANDOFF.md`

### 3.1 Создать проект

1. Зарегистрируйся на [supabase.com](https://supabase.com) — бесплатного тарифа хватит
2. **New project**. Регион выбирай ближе к твоим клиентам (для России/Европы — Frankfurt)
3. Пароль от базы, который он попросит, **сохрани** — второй раз его не покажут

### 3.2 Создать таблицу

Открой в Supabase **SQL Editor → New query**, скопируй туда полностью содержимое файла
`supabase/leads.sql` и нажми **Run**. Появится таблица `leads`.

Что делает этот скрипт, кроме создания таблицы: включает защиту RLS и **не создаёт ни
одной политики доступа**. Это значит, что публичным ключом твою базу заявок нельзя ни
прочитать, ни изменить — писать может только сервер сайта. Так и задумано.

### 3.3 Забрать ключи

В Supabase: **Project Settings → API**. Нужны два значения:

- **Project URL** — вида `https://xxxxx.supabase.co`
- **service_role** ключ — в разделе Project API keys, нажми «reveal»

⚠️ `service_role` — это **полный доступ к базе в обход всех проверок**. Правила:

- живёт только в `.env.local` (файл уже в `.gitignore`, в git не попадёт)
- никогда не пересылай его в чатах, скриншотах, issues
- **никогда** не переименовывай переменную в `NEXT_PUBLIC_...` — этот префикс означает
  «отдать в браузер каждому посетителю»
- если всё же утёк — иди в Supabase и сделай ротацию ключа, старый сразу перестанет работать

### 3.4 Вписать ключи в проект

В папке `studio` нужен файл **`.env.local`** такого вида:

```
NEXT_PUBLIC_SITE_URL=http://localhost:3000
NEXT_PUBLIC_SUPABASE_URL=https://xxxxx.supabase.co
SUPABASE_SERVICE_ROLE_KEY=твой_service_role_ключ
```

> Не создавай его Блокнотом — он молча сохранит файл как `.env.local.txt`, и ничего не
> заработает. Проще всего попросить Claude: «создай .env.local с такими значениями».
> Образец лежит рядом в `.env.example`.

Перезапусти `npm run dev` — переменные читаются только при старте.

### 3.5 Проверить

Отправь заявку через форму на сайте, потом в Supabase открой **Table Editor → leads**.
Строка должна появиться.

Если строки нет — смотри окно терминала, где запущен `npm run dev`. Там будет либо
`[leads] Supabase не настроен` (значит `.env.local` не подхватился), либо
`[leads] insert failed` с текстом ошибки от базы.

### ⚠️ Важно про бесплатный тариф

**Проекты Supabase на бесплатном тарифе засыпают после ~недели без обращений.** А базу
дёргает только отправка формы. То есть на спокойном сайте она может уснуть — и заявка не
запишется именно тогда, когда она нужна.

**✅ Решено:** на Vercel настроен ежедневный Cron (`vercel.json` →
[`src/app/api/keepalive/route.ts`](src/app/api/keepalive/route.ts)), который лёгким
запросом будит Supabase — до недельного порога засыпания никогда не доходит. Эндпоинт
защищён секретом `CRON_SECRET` (Vercel сам присылает его в заголовке `Authorization` при
вызове по расписанию, поэтому дёрнуть его снаружи без секрета нельзя).

Но не полагайся только на это как на единственную страховку — Telegram (Шаг 4) всё равно
должен быть настроен: если когда-нибудь cron отключат или Vercel сменит поведение,
уведомление о заявке всё равно дойдёт.

## Шаг 4. Уведомления о заявках в Telegram

**Код написан и проверен — осталось вписать два ключа.** Пока их нет, отправка в Telegram
просто пропускается, и сайт работает как раньше.

> Claude: `Помоги настроить уведомления в Telegram по Шагу 4 из HANDOFF.md`

### 4.1 Что нужно от тебя

1. В Telegram найди **@BotFather**, отправь `/newbot`, придумай имя и username бота.
   В ответ придёт **токен** вида `123456789:AAxxxxxxxxxxxxxxxxxxxxx`
2. Узнай, **куда** присылать:
   - себе лично — напиши боту **@userinfobot**, он вернёт твой числовой `id`
   - в общий чат команды — добавь своего бота в группу, затем открой в браузере
     `https://api.telegram.org/bot<ТОКЕН>/getUpdates` и найди там `"chat":{"id":-100...}`
     (у групп id отрицательный)
3. Добавь в `.env.local`:

   ```
   TELEGRAM_BOT_TOKEN=токен_от_BotFather
   TELEGRAM_CHAT_ID=id_куда_писать
   ```

   Без префикса `NEXT_PUBLIC_` — токен бота такой же секрет, как ключ базы.

### 4.2 Как это устроено в коде

Отправка живёт в [`src/lib/telegram.ts`](src/lib/telegram.ts), вызывается из
[`src/app/actions.ts`](src/app/actions.ts). Требования, по которым это сделано —
менять поведение можно только понимая их:

- Отправка через `fetch` на `https://api.telegram.org/bot<TOKEN>/sendMessage`,
  методом POST, в теле `chat_id` и `text`. Новых зависимостей не нужно.
- **Отправлять простым текстом, без `parse_mode`.** Если включить Markdown или HTML,
  то любой символ `_`, `*` или `<` в имени или сообщении клиента сломает отправку —
  и заявка потеряется из-за апострофа в тексте.
- **Уведомление не должно зависеть от записи в базу, и наоборот.** Помним, что
  бесплатный Supabase умеет засыпать: если `insert` упал, уведомление всё равно
  обязано уйти. Считать отправку успешной, если сработал хотя бы один канал.
- **Ошибка уведомления не должна ломать форму для клиента.** Оборачивать в `try/catch`
  и логировать: посетитель не виноват, что упал Telegram, он должен увидеть «спасибо».
- Поставить таймаут на запрос (`AbortSignal.timeout(5000)`), чтобы подвисший Telegram
  не держал отправку формы.
- Если переменных `TELEGRAM_*` нет — просто пропускать отправку, как это уже сделано
  для Supabase в [`src/lib/supabase.ts`](src/lib/supabase.ts). Сайт должен оставаться
  рабочим без ключей.
- В сообщение положить: имя, email, компанию, бюджет, текст, язык страницы.

### 4.3 Проверить

Отправь тестовую заявку — сообщение должно прийти в Telegram за пару секунд.

Отдельно проверь запасной путь: временно испорти токен и отправь заявку ещё раз. Если
база подключена, посетитель всё равно увидит «спасибо» — заявка сохранена, а сбой
Telegram его не касается. А вот если **не доставил ни один канал**, форма честно
покажет «не получилось» и предложит почту и Telegram: терять заявку молча хуже, чем
попросить человека написать напрямую.

## Шаг 5. Видео — куда заливать

Сейчас в `public/media/` лежат **открытые тест-ролики** (Big Buck Bunny, Sintel,
Jellyfish). К агентству они отношения не имеют и в продакшн идти не должны.

> Claude: `Помоги перевести видео на Bunny Stream по Шагу 5 из HANDOFF.md`

### Куда НЕ надо

- **В папку `public/` рядом с сайтом.** Гигабайты попадут в git и в каждую сборку,
  ролик поедет одним куском без переключения качества, а трафик посчитают по тарифу
  хостинга — это самый дорогой способ раздавать видео.
- **В Google Drive.** Он отдаёт файл, а не видеопоток: прямые ссылки нестабильны,
  перемотка работает плохо, при трафике включается квота.
- **В Supabase Storage.** Это хранилище файлов, а не видеоплатформа: нет перекодирования
  и нет адаптивного качества.

Ключевая причина всех трёх пунктов одна: они отдают **один тяжёлый файл**. Шоурил в 4K
на мобильном интернете будет останавливаться на загрузку. Видеоплатформы делают из
ролика несколько версий разного качества и переключают их на ходу — для витрины
видеоагентства это критично.

### Куда надо

| | Как платят | Когда брать |
|---|---|---|
| **Bunny Stream** | за хранение + за трафик, дешевле остальных | **Дефолт для этого сайта.** Кодирование, плеер и превью включены |
| **Cloudflare Stream** | за минуты хранения и минуты просмотра | Если хочется предсказуемого счёта или уже пользуешься Cloudflare |
| **Mux** | дороже, по минутам | Если нужна аналитика: сколько людей досмотрело ролик до конца |

Цены сверяй на сайтах провайдеров — они меняются, и я не хочу, чтобы ты планировал
бюджет по устаревшей цифре из markdown-файла.

### Как переехать

Хорошая новость: **менять компоненты не придётся.** Все три платформы уже поддержаны в
[`src/lib/video.ts`](src/lib/video.ts). Правится только `provider` у записей в
[`src/lib/content.ts`](src/lib/content.ts):

```ts
// было
{ provider: "file", src: "/media/work-01.mp4", poster: "/media/work-01.jpg" }

// стало
{ provider: "bunny", libraryId: "12345", videoId: "abc-def", poster: "/media/work-01.jpg" }
```

**Одно исключение — хиро-луп на первом экране.** Его надо оставить обычным файлом
(`provider: "file"`). Он короткий, немой и запускается сам, а если завернуть его в плеер
платформы, страница потянет лишний сторонний скрипт и первый экран станет грузиться
заметно медленнее. Портфолио и шоурил — на платформу, фоновый луп — файлом.

Постеры (`poster`) стоит оставить своими: на карточках сразу грузится картинка, а плеер
включается только по клику. Посетитель видит именно постер, поэтому его качество важнее,
чем кажется.

### Подготовить файлы перед загрузкой

Если исходники лежат на Google Drive, забрать их удобно через `rclone`. Перед загрузкой
имеет смысл перегнать в веб-профиль:

```bash
ffmpeg -i исходник.mov -c:v libx264 -crf 20 -preset slow \
  -c:a aac -b:a 128k -movflags +faststart готовый.mp4
```

`+faststart` переносит индекс в начало файла — без него браузер ждёт загрузки целого
файла перед началом воспроизведения.

## Шаг 6. Выложить сайт в интернет (Vercel)

[Vercel](https://vercel.com) — это разработчики Next.js, на котором сделан сайт. Для
такого проекта это правильный выбор, бесплатного тарифа хватит с запасом.

**Сначала сделай [Шаг 8](#шаг-8-настроить-git-важно) (git) — без него деплоить нечего.**

> Claude: `Помоги задеплоить сайт на Vercel по Шагу 6 из HANDOFF.md`

### 6.1 Залить код на GitHub

Репозиторий должен создаваться **из папки `studio`**, а не из `C:\Cloude`. Тогда Vercel
сам всё найдёт и не придётся возиться с настройкой вложенных папок.

Создай пустой репозиторий на GitHub (**приватный**, если не хочешь публиковать код) и
выполни в `C:\Cloude\studio`:

```
git remote add origin https://github.com/ТВОЙ_ЛОГИН/kadr.git
git branch -M main
git push -u origin main
```

Перед первым `push` убедись, что `.env.local` **не** попал в список файлов: он в
`.gitignore`, но лучше проверить командой `git status`.

### 6.2 Импортировать в Vercel

1. Зарегистрируйся на Vercel через свой GitHub-аккаунт
2. **Add New → Project → Import** свой репозиторий
3. Framework определится как Next.js автоматически — ничего не меняй
4. Разверни блок **Environment Variables** и добавь:

   | Имя | Значение |
   |---|---|
   | `NEXT_PUBLIC_SITE_URL` | боевой адрес сайта, например `https://nitroreel.studio` |
   | `NEXT_PUBLIC_SUPABASE_URL` | из Supabase |
   | `SUPABASE_SERVICE_ROLE_KEY` | из Supabase |
   | `TELEGRAM_BOT_TOKEN` | если сделал Шаг 4 |
   | `TELEGRAM_CHAT_ID` | если сделал Шаг 4 |
   | `CRON_SECRET` | см. Шаг про keepalive выше — тот же секрет, что и локально |
   | `GEMINI_API_KEY` | если включил чат-виджет — см. [Шаг 9](#шаг-9-чат-виджет-поддержки) |

5. **Deploy**

`NEXT_PUBLIC_SITE_URL` влияет на ссылки в `sitemap.xml`, canonical и превью в соцсетях.
Если оставить там `localhost`, поисковики и мессенджеры получат нерабочие адреса.

### 6.3 Свой домен

**Settings → Domains → Add**, дальше Vercel покажет, какие DNS-записи прописать у
регистратора домена. Обновление DNS занимает от минут до пары часов. HTTPS-сертификат
Vercel выдаст сам.

### 6.4 После деплоя проверь

- открывается корень и редиректит на `/ru`
- переключатель языка гоняет между `/ru` и `/en`
- открываются `/sitemap.xml` и `/robots.txt`, и адреса внутри — боевые, не localhost
- **отправь тестовую заявку** и убедись, что она дошла до базы и в Telegram
- как выглядит ссылка на сайт, если кинуть её себе в Telegram (это проверка OG-картинки)

### Важно про переменные

Если поменял переменную в настройках Vercel — **нужен новый деплой**, само не подхватится.
Кнопка: **Deployments → ⋯ → Redeploy**.

## Шаг 7. Заменить демо-контент

Сайт полностью рабочий, но наполнение придумано. Перед показом клиентам замени:

| Что | Где лежит |
|---|---|
| **Видео** — тест-ролики | `public/media/`, см. [Шаг 5](#шаг-5-видео--куда-заливать) |
| **Кейсы, клиенты, цифры результатов** | [`src/lib/content.ts`](src/lib/content.ts) |

Тексты хранятся сразу в двух языках. Если правишь русскую версию — правь и английскую,
иначе проект **не соберётся**. Это не баг, а специальная защита от забытых переводов:
`npx tsc --noEmit` покажет, где именно пропущено.

Проще всего дать Claude готовые тексты и попросить расставить — он знает, где что лежит.

## Шаг 9. Чат-виджет поддержки

Кнопка внизу справа открывает чат с ИИ-ассистентом — отвечает на вопросы про сроки,
стоимость и жанры прямо на основе FAQ с сайта, бесплатно, без подписок (бесплатный тир
Google Gemini). Уже подключено и проверено, но если ключ когда-нибудь придётся обновить
или переносишь сайт на новый Google-аккаунт:

1. [aistudio.google.com/apikey](https://aistudio.google.com/apikey) → войти через Google
   → **Create API key** (бесплатно, без карты)
2. Добавить в `.env.local` (локально) и в Environment Variables Vercel (боевой):
   ```
   GEMINI_API_KEY=твой_ключ
   ```
3. Перезапустить `npm run dev` / передеплоить на Vercel

**Бесплатный лимит.** У модели `gemini-flash-latest` квота порядка 10 запросов в минуту
и несколько сотен в день — с запасом на сайт-агентство. Свой лимит в коде (6 вопросов в
минуту с одного посетителя) стоит ниже квоты Google специально, чтобы виджет вежливо
попросил подождать, а не поймал ошибку от Google. Если трафик сильно вырастет и лимита
перестанет хватать — единственный платный шаг во всём проекте: включить биллинг в Google
AI Studio (тогда лимиты снимаются, тарификация по токенам).

**Если бот отвечает не по делу или устарел.** Он берёт ответы из тех же вопросов и услуг,
что показаны в разделах «Вопросы» и «Услуги» на сайте (`dictionaries.ts`) — обновляешь
текст там, бот отвечает по-новому автоматически, отдельно ничего не переписывай.

## Что делать, если что-то пошло не так

**Пошёл спам через форму.** Сейчас стоит honeypot — скрытое поле, которое заполняют
только боты. Если этого перестанет хватать, правильный следующий шаг — не усложнять
проверки, а поставить **Cloudflare Turnstile**: бесплатно и для человека незаметно.

**Ограничение частоты отправок работает не полностью.** Так и есть: счётчик (3 заявки в
минуту с одного адреса) живёт в памяти процесса, а на Vercel процессов несколько. Это
осознанный компромисс. Если понадобится жёстко — Upstash Redis или тот же Postgres в
Supabase, чтобы не плодить лишние сервисы.

**Заявки перестали приходить.** По порядку: не уснул ли проект Supabase (зайди в панель,
он предложит разбудить) → на месте ли переменные окружения в Vercel → что в логах.

**Где смотреть логи.** Локально — в окне терминала с `npm run dev`. На Vercel —
**Deployments → выбрать деплой → Runtime Logs**. Все сообщения про заявки помечены
префиксом `[leads]`.

**Сборка падает после правки текстов.** Почти всегда это забытый перевод. Запусти
`npx tsc --noEmit` — он покажет точное место.

**Утёк секретный ключ** (закоммитил, переслал, показал в стриме). Сделай ротацию в
панели сервиса: Supabase — Project Settings → API, Telegram — `/revoke` у @BotFather.
Удалить сообщение недостаточно: если ключ попал в git, он остаётся в истории навсегда.

**Хочу выгрузить заявки.** В Supabase: Table Editor → `leads` → экспорт в CSV. На
бесплатном тарифе автоматических бэкапов нет, так что если заявки важны — выгружай
периодически или ставь платный тариф.

## Для Claude: как вести пользователя по этому файлу

Владелец проекта — не разработчик. Если он просит настроить проект, «запустить», «чтобы
работало» или ссылается на этот файл:

1. **Сначала спроси, какая у него цель сейчас**, и предложи маршрут, а не вываливай все
   шаги сразу. Типичные ветки: «просто посмотреть локально» (Шаг 2), «начать принимать
   заявки» (Шаги 3 → 4), «выложить в интернет» (Шаги 8 → 6), «залить настоящие видео»
   (Шаг 5).
2. **Проверяй состояние, а не верь таблице статусов** в начале файла — она отражает
   момент передачи и могла устареть. Загляни, есть ли `.env.local`, инициализирован ли
   git, какие `provider` стоят в `content.ts`.
3. **Секреты запрашивай, но не показывай.** Ключи и токены пиши в `.env.local` и не
   выводи их значения в чат. Если пользователь прислал ключ в сообщении — напомни, что
   такие вещи лучше не пересылать, и предложи ротацию, если он попал куда-то ещё.
4. **Делай сам всё, что можно сделать за него:** создать файлы, вписать переменные,
   написать код, запустить проверки. Оставляй ему только то, что физически требует его
   участия — регистрацию в сервисах, копирование ключей из панелей, настройку DNS.
5. **После каждого шага проверяй результат** (`npm run build`, `npx tsc --noEmit`,
   тестовая отправка формы) и **обновляй таблицу статусов** в начале этого файла.
6. **Если git ещё не настроен — предложи это первым делом.** У пользователя нет
   возможности откатить неудачную правку, и он об этом не думает.
7. **Не удаляй разделы этого файла как «уже сделанные»** — он остаётся справочником
   на случай, если что-то отвалится через полгода.
